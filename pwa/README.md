# FecalVision — web app

The FecalVision Progressive Web App: React 19 + Vite, with TensorFlow.js running the models in the browser. For what the project is and how well the model performs, see the [main README](../README.md).

## Setup

You need Node.js 20 or newer.

```bash
npm install
```

Run `npm install` again whenever `package.json` changes (after a pull, for example). If you skip it, Vite fails with errors like `Failed to resolve import "@tensorflow/tfjs-backend-wasm"`.

### Testing on a phone

Browsers only allow the camera on `https` or `localhost`, so a phone needs the `:phone` scripts:

1. Connect the phone and the computer to the same Wi-Fi.
2. Run `npm run dev:phone` and open the **Network** address it prints (`https://192.168.x.x:5173`) on the phone.
3. The certificate is self-signed, so the browser warns once. Choose **Advanced**, then **Proceed**.

If the phone can't connect, Windows Firewall may be blocking Node.js on private networks.

Use `preview:phone` to test offline mode and installing. The dev server's service worker doesn't behave exactly like the real one.

### Key files in `src/lib/`

| File | Responsibility |
| --- | --- |
| `fecalvision.js` | Loads the disease model, preprocesses photos, runs it, applies calibration |
| `gate.js` | The dropping check that runs before the disease model |
| `backend.js` | Chooses WebGL or WebAssembly per device by measuring numeric drift |
| `quality.js` | Live light, focus and distance checks on camera frames |
| `analysisInput.js` | Decodes photos and chooses which part the model sees |
| `history.js` | Scan history in IndexedDB (on the device only) |
| `export.js`, `zip.js` | CSV / JSON / ZIP export |
| `report.js` | The shareable result image |

## How inference works

- **Input contract:** `float32 [1, 224, 224, 3]` with values **0–255**, centre-cropped to a square, then resized. Normalisation happens *inside* the model graph, so don't divide by 255 or rescale in JavaScript. This applies to both models. `gate.js` imports `preprocess()` from `fecalvision.js` so both models see exactly the same pixels.
- **Classes:** read from `class_names.json` (0 Coccidiosis, 1 Healthy, 2 Newcastle Disease, 3 Salmonella). Never work them out from folder names.
- **Calibration:** `calibration.json` holds the temperature (0.74) and the confidence threshold (0.90), both fitted on the validation split. Below the threshold the app answers "Not clear enough to call".
- **Dropping check:** `model-gate/gate.json` holds its threshold (0.08, deliberately low so real droppings are rarely blocked). If the check can't load, it fails open and scanning continues.
- **Backend choice:** on first run, `backend.js` runs the same test inputs on WebGL and WebAssembly. If WebGL's results drift too far (common on mobile GPUs that compute at reduced precision), the device uses WebAssembly. Threaded WASM is turned off because of a hang bug in this TF.js version.
- **Offline:** the service worker precaches the app, the two models in use and the `.wasm` files. Model weights are also cached in IndexedDB.

## Changing the model

1. Put the exported TF.js graph model in a new `public/model-<name>/` folder with `model.json`, the weight shards, `class_names.json` and `calibration.json`.
2. Point `MODEL_DIR` in `src/lib/fecalvision.js` at it.
3. Update `src/content/models.js` with the new test results. They appear in Help, so they must match the new model.
4. Add any folders that are no longer used to `EXCLUDED_MODEL_GLOBS` in `vite.config.js`, so phones don't download them.
5. If the download size changed, update `MODEL_DOWNLOAD_MB` in `src/content/performance.js`.

## Regenerating assets

These outputs are committed, so you only need to run them when the input changes:

```bash
node scripts/make-icons.mjs   # after replacing scripts/logo-source.svg
node scripts/copy-wasm.mjs    # after upgrading @tensorflow/tfjs-backend-wasm
```

If the logo's layout changes, check the `CROP` and `TAB_CROP` values in `make-icons.mjs`.

## Deployment

The app is deployed on Vercel, with `pwa/` as the project root. `vercel.json` provides:

- a rewrite of every path to `index.html`, so screens load from any URL;
- the `Cross-Origin-Opener-Policy` and `Cross-Origin-Embedder-Policy` headers, which make the page cross-origin isolated. Because of this, everything must be self-hosted: a script, image or font from another site will be blocked.

Each build shows the commit id and build time in the app (menu → Diagnostics), so you can tell which version a phone is running.

## Troubleshooting

| Problem | Fix |
| --- | --- |
| `Failed to resolve import …` | Run `npm install` |
| Camera doesn't open on a phone | Use `npm run dev:phone` and open the **https** address |
| Phone keeps showing an old version | Close and reopen the app. The service worker updates in the background, and the new version loads on the next launch |
| Old icon after a logo change | Android updates it within a day or so. On iPhone, remove the app from the home screen and add it again |
| Results differ between devices | Open Diagnostics from the menu. That phone may be using WebGL with reduced precision. Tap "Clear cached choice and test again" to measure again |
